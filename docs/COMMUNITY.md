# Working with people

Start with the [pinned welcome discussion](https://github.com/thinkhome-org/full-github/discussions/10).

| Need | Channel | Record |
| --- | --- | --- |
| Installation or workflow question | Q&A Discussions | Goal, version/host when relevant, sanitized evidence and accepted answer |
| Proposal or unclear configuration choice | Ideas Discussions | Intended outcome, options/tradeoffs, sources and recorded decision |
| Reproducible defect | Issue form | Expected/actual behavior, reproduction and verification |
| Code/configuration change | Linked pull request | Before/desired state, tests, source/history links and review conversation |
| Security vulnerability | Private reporting | Confidential evidence and coordinated disclosure |

Accepted work is linked to an issue, milestone and Project item. Preserve its original discussion and any review history. A later decision should explain why it supersedes the earlier choice.

Codex-assisted maintenance is identified in the welcome discussion. Real human approvals, reactions and answers come from their actual authors. Single-maintainer workflows do not pretend to have independent peer approval. Required reviews and environment approvals must be completed by eligible people through GitHub.

Use the [history guide](../skills/full-github/references/history-interaction.md), [configuration decisions](CONFIGURATION.md) and [contribution guide](../CONTRIBUTING.md). Share only sanitized execution metadata. The local journal records CLI attempts and verification references; authenticated GitHub records retain the native actor, review and publication history.
