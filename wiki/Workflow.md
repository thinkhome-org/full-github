# Active work and conversations

Follow the [issue lifecycle runbook](https://github.com/thinkhome-org/full-github/blob/main/skills/full-github/references/issue-lifecycle.md). Every substantial task begins with a real issue and a new kickoff comment. Material findings, changed decisions, review evidence and verified delivery become separate comments in chronological order. Preserve reporter content and earlier comments. Concurrent workers must not replace a shared comment.

Issues have chronological comments and quote links. For nested topics use Discussion replies or PR review threads; use native child issues for independently accepted work and blockers for real ordering.

Inspect native type in addition to labels, actual assignment, shared fields, Project membership/status/priority, milestone, parent/sub-issues, dependencies, artifacts and linked branch/PR. Shared owner fields can be restricted while Project-local fields are public; preserve their visibility. Do not fabricate estimates, relationships or approvals.

The current work in [issue 14](https://github.com/thinkhome-org/full-github/issues/14) demonstrates native children, blocker relation, attached plan, chronological comments and delivery tracking. Earlier completed issues have explicitly retrospective delivery comments, preserving the real posting date.

For full setup/audit run the [completion gate](https://github.com/thinkhome-org/full-github/blob/main/skills/full-github/references/completion.md) against every catalog capability. It rejects unfinished records and missing evidence; it does not independently establish that evidence is true. Host skill selection and actual credentials remain required.
